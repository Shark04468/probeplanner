## Recheck Without Private Local Files

Use Python 3.10 and the release's locked backend environment. Place the public
ZIP and `PUBLIC_EVIDENCE_MANIFEST.json` together in an evidence directory. From
the source root run, replacing `EVIDENCE_DIR` and `NEW_REPORT.json` with paths:

```sh
python scripts/release/verify_public_evidence.py \
  --evidence-dir EVIDENCE_DIR \
  --resolve-models \
  --output NEW_REPORT.json
```

The output must be a new file. The verifier checks the pinned public manifest,
actual ZIP member hashes, original-identity links, request/model bindings,
recorded strict outcomes, coverage, conflict freedom and exact certificates.
With `--resolve-models`, it independently re-solves the 101 archived models using
the existing SciPy/HiGHS model solver. It does not regenerate candidates or
validate anatomy. Without this flag it checks recorded certificates only.

Retrospective and confirmation evidence remain separate: 89 positive and nine
expected negative cases in the former; 12 positive and one reused negative
control in the latter. The observed re-solve matched all 89 and all 12 recorded
counts with zero timeouts. These are not new independent validation cases.

## Original-To-Derivative Audit

Maintainers retaining the private original bundle can additionally run:

```sh
python scripts/release/verify_projection_lineage.py \
  --original-dir PRIVATE_EVIDENCE_DIR \
  --public-dir EVIDENCE_DIR \
  --output NEW_LINEAGE_REPORT.json
```

The independent comparison does not call the projection builder's transform
function. It checks all original-to-public identities and changed JSON values,
then scans decompressed UTF-8 text for Windows absolute paths and long credential
assignment patterns. A clean pattern scan is not a comprehensive security or
licensing review. Never upload `LOCAL_SOURCE_MAP_PRIVATE.json` or the original
private bundle as part of the public projection.

Archived Python campaign entry points retain archival status. Path placeholders
do not turn them into portable runners. A separately documented
[portable execution route](v0.3.0-reproduction.md) now stages the unchanged
scientific modules with explicit path bindings and the separately bound public
profile. No original request, v4 failure, old v5 evidence, or exact-oracle output
has been edited by this packaging operation.

## Interpretation

The exact claim concerns minimum cardinality in each archived regenerated,
strictly filtered finite candidate pool. This package does not support a
continuous-space global optimum, subject-specific TRE, bregma/lambda accuracy,
native-space surgical safety or histological implantation accuracy. Component
reports deliberately retain `releaseAcceptance: false`; the complete release
and data-delivery gates are separate.
